# AGENTS.md — контекст проекта Crane Monitor

`kranTK` — статический демо-стенд (MVP) системы мониторинга автокранов
Crane Monitor. Бэкенда нет: интерфейс работает на статических
данных, детерминированно генерируемых в браузере. Цель — показать дизайн и
логику, в первую очередь **рабочую хронологию работы крана**.

## Команды

```bash
npm install
npm start                 # собрать и открыть на localhost:4173 — для показа
npm run dev               # dev-сервер с горячей перезагрузкой (localhost:5173)
npm run build             # tsc -b && vite build -> dist/
npm run preview           # отдать уже собранный dist/
npm run build:standalone  # автономный HTML в dist-standalone/ (открывается с диска)
npm run typecheck         # только проверка типов
npm run format            # Prettier по всему проекту
```

Есть и запускалки без npm: `./scripts/start.sh` (macOS/Linux) и
`scripts\start.cmd` (Windows) — сами проверят Node и поставят зависимости.

Деплой — GitHub Actions (`.github/workflows/deploy.yml`): собирает и
публикует `dist/` на GitHub Pages, ветка `gh-pages` не нужна. Pages должны
быть включены вручную (Settings → Pages → Source: GitHub Actions) и
репозиторий должен быть публичным — подробности в `docs/07-deploy.md`.

## Архитектура в трёх предложениях

`src/domain/` — единственный источник данных: статический парк из 8 кранов
(`fleet.ts`) плюс генератор суточной телеметрии, интервалов и событий
(`telemetry.ts`), детерминированный от seed «id крана + дата».
`src/features/` — три экрана поверх этих данных: `auth` (вход `demo`/`demo`),
`dashboard` («Главный экран») и `monitoring` («Мониторинг» с вкладками
«Обзор» и «Хронология»); общий каркас и hash-роутинг — в `src/app/`.
Компоненты только читают домен и рисуют; никаких чисел в вёрстке.

## Границы работ

Реализуются **только** разделы «Главный экран» и «Мониторинг».
Пункты «Журнал», «Диагностика», «Отчёты» остаются в меню как недоступные
в демо — не реализовывать без отдельной просьбы.

## Соглашения

- Язык интерфейса, комментариев и документации — русский.
- Стили — обычный CSS с переменными из `src/styles/tokens.css`.
  Новых цветов не вводить, брать токен; нет подходящего — добавить в токены.
- Один экран = одна папка в `src/features/`, внутри `*.tsx` + `*.css`.
- Данные не хардкодятся в компонентах: всё через `src/domain/`.
- Роутинг — по hash: `#/dashboard`, `#/monitoring/<id>`.
- Форматирование чисел и времени — только через `src/domain/format.ts`,
  чтобы разделители и единицы были одинаковыми везде.
- Стиль кода задан `.prettierrc.json` (без точек с запятой, одинарные
  кавычки, ширина 100) и `.editorconfig` (LF, 2 пробела, финальный перевод
  строки). Перед коммитом — `npm run format`; проверить без правок —
  `npm run format:check`.

## Жёсткие ограничения

1. **Демо-время зафиксировано:** `DEMO_NOW = 02.09.2026 11:39`
   (`src/domain/time.ts`). Не заменять на `new Date()` — стенд должен
   выглядеть одинаково в любой день, иначе ночью демо окажется пустым.
2. **Генератор обязан оставаться детерминированным.** Seed = `id + дата`.
   Любой `Math.random()` в домене ломает «Архив»: одна и та же дата начнёт
   давать разные данные.
3. **Авторизация — витрина, а не защита.** Пара `demo`/`demo` лежит в
   клиентском коде и проверяется в браузере; исходники публичны. Не выдавать
   за средство защиты и не хранить за ней ничего чувствительного.
4. **`base` для Vite** берётся из `BASE_PATH`, пути к ассетам не хардкодить.
   Workflow сам подставляет `/` для корневого сайта `<owner>.github.io` и
   `/<repo>/` для проектного.

## Подводные камни

- **Макеты противоречат друг другу.** У SANY в `Главный экран.dc.html`
  текущая загрузка 8 % (0.68 т), а в `Мониторинг крана v2.dc.html` — 62 %
  (18.60 из 30.00 т). Взят вариант из v2: реализуем именно его, и SANY
  открыт по умолчанию. Не «чинить» это по первому попавшемуся макету.
- **Геометрия связана.** Вылет и высота не независимые поля, а
  `вылет = длина·cos(угол) − 0.85`, `высота = длина·sin(угол) + 0.1`
  (`src/domain/telemetry.ts`). Правка одного числа без остальных даёт
  физически невозможную картинку на схеме крана.
- **Хронология — не картинка.** Полоса и таблица интервалов строятся из
  ряда точек; курсор двигает индекс по ряду, и все показатели на экране
  пересчитываются на этот момент. Заглушки с процентами ширины из макета
  использовать нельзя.
- **Краны без связи.** У `status: 'off'` поле `lastSeenMin` задаёт минуту
  последнего контакта, `-1` — данных за сутки нет вообще. Код везде должен
  переживать `loadPct === null`.
- **`noUnusedLocals` включён** — неиспользованный импорт валит `npm run build`.
- **`dist/index.html` не открывается с диска:** браузер не грузит внешние
  ES-модули по `file://`. Для показа без сервера есть
  `npm run build:standalone` — он вшивает скрипты и стили в одну страницу
  (`scripts/make-standalone.mjs`).
