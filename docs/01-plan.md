# План работ — Crane Monitor (MVP демо)

Статус: MVP готов (см. таблицу этапов)
Дата составления: 2026-09-02

## 1. Цель

Собрать статический демо-стенд («витрину») системы мониторинга автокранов
Crane Monitor по дизайну `Мониторинг крана v2.dc.html`,
пригодный для публикации на GitHub Pages.

MVP для демонстрации: реального бэкенда нет, все данные — статические
(детерминированно генерируемые в браузере), но полностью связные и
правдоподобные.

## 2. Границы (scope)

### Входит

- Экран входа с проверкой логина/пароля `demo` / `demo`.
- Раздел **Главный экран** (обзор парка из 8 кранов).
- Раздел **Мониторинг** (карточка одного крана: вкладки «Обзор» и «Хронология»).
- Рабочая хронология: воспроизведение, скорость, перемотка, скраб по шкале,
  пересчёт всех показателей на выбранный момент времени.
- Режимы Live / Архив с переключением даты.
- Сборка Vite → публикация на GitHub Pages через GitHub Actions.
- Локальный запуск: dev-сервер, локальная статика одной командой и
  автономный HTML-файл, работающий с диска без сервера.

### Не входит

- Разделы «Журнал», «Диагностика», «Отчёты» — пункты меню присутствуют,
  но помечены как недоступные в демо.
- Реальная карта Яндекса (используется стилизованная схематичная заглушка,
  как в макете).
- Любое сетевое взаимодействие, API, БД, реальная аутентификация.

## 4. Ключевые решения

1. **Стек — Vite 8 + React 19 + TypeScript.**
   Дизайн из Claude Design описан как реактивный компонент (`DCLogic`,
   `state` + `renderVals()`), поэтому React переносит его 1:1.
   Vite даёт статическую сборку без сервера — то, что нужно для Pages.

2. **Роутинг — hash (`#/dashboard`, `#/monitoring/2483580`).**
   GitHub Pages не умеет rewrite на `index.html`; hash-роутинг убирает
   проблему 404 при перезагрузке страницы без костыля с `404.html`.

3. **Данные — детерминированный генератор от seed.**
   Ключ seed = `crane.id + дата`. Один и тот же кран и день всегда дают
   одну и ту же телеметрию, поэтому «Архив» листается по датам и остаётся
   осмысленным, а хронология воспроизводится по реальному ряду точек, а не
   по захардкоженным процентам ширины из макета.

4. **Авторизация — клиентская заглушка.**
   Пара `demo`/`demo` проверяется в браузере, флаг входа хранится в
   `sessionStorage`. Это витрина доступа, а не защита: см.
   `docs/06-auth.md`, раздел «Ограничения».

5. **Стили — обычный CSS с переменными-токенами.**
   Макет полностью на инлайн-стилях; переносим значения в CSS-переменные
   (`src/styles/tokens.css`), чтобы палитра и типографика были в одном месте.

## 5. Критерии приёмки

- [x] `npm run build` проходит без ошибок, `npm run typecheck` чист.
- [x] Без верных `demo`/`demo` не отображается ни один экран приложения.
- [x] «Главный экран» показывает 8 кранов, разворачивающиеся карточки,
      сводку, карту-заглушку и раскрываемые панели.
- [x] «Мониторинг» показывает выбранный кран, вкладки «Обзор»/«Хронология»,
      переключение Live/Архив и листание дат.
- [x] Хронология: кнопка ▶ запускает движение курсора, скорость
      1x/2x/4x/8x, шаг ««»/»»», клик и перетаскивание по шкале, все
      показатели пересчитываются на момент курсора.
- [x] Диапазоны «24 часа» / «Смена» / «7 дней» переключаются и меняют шкалу.
- [x] Сборка публикуется на GitHub Pages воркфлоу `deploy.yml`.
