## Как устроены макеты

Файлы `.dc.html` — не статическая вёрстка, а реактивные компоненты:

- разметка на инлайн-стилях с плейсхолдерами `{{ имя }}`;
- управляющие теги `<sc-if>` и `<sc-for>` вместо условий и циклов;
- внизу `<script type="text/x-dc">` с `class Component extends DCLogic`,
  у которого есть `state` и метод `renderVals()`, возвращающий значения
  для плейсхолдеров.

По сути это React-компонент в другой записи, поэтому перенос почти
дословный: `state` → `useState`, `renderVals()` → тело компонента,
`sc-for` → `.map()`, `sc-if` → условный рендер.

## Скриншоты реального сайта

Два PNG в проекте Claude Design — самый ценный источник фактуры: это не
мокап, а рабочая система заказчика. Из них взяты блоки, которых нет в макетах:

- на главном экране — карта Яндекса, фотографии техники, «Состояние парка»
  (кольцо), «Активность за день», «Динамика загрузки» за 15 дней;
- на мониторинге — схема крана с размерами, блоки «Двигатель»,
  «Гидравлика / Нагрузка», «Положение», плеер хронологии за 24 часа.

Числа на скриншотах (SANY: угол 68.26°, стрела 31.56 м, вылет 10.84 м)
совпадают с массивом `RAW` из макета «Главный экран» — то есть макет
рисовался с живых данных. Поэтому паспорт и параметры кранов в
`src/domain/fleet.ts` взяты именно оттуда.

## Референс-система

Рабочая система заказчика (адрес и демо-доступ есть у команды, в публичных
материалах не приводятся). Это SPA: по HTTP отдаётся пустая оболочка,
полезного HTML не получить — смотреть только в браузере.

## Что делать при расхождении макетов

Макеты противоречат друг другу в текущей загрузке SANY STC300T5:
«Главный экран» показывает 8 % (0.68 т), «Мониторинг крана v2» — 62 %
(18.60 из 30.00 т). Взят вариант из v2, потому что реализуется именно он и
этот кран открыт по умолчанию. Данные в приложении единые:
`src/domain/fleet.ts` — один источник для обоих экранов.

Общее правило приоритета: **«Мониторинг крана v2»** → скриншоты рабочего
сайта → **«Главный экран»**.
