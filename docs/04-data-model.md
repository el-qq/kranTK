# Модель данных и генератор телеметрии

Весь слой данных — в `src/domain/`. Компоненты только читают его; чисел,
зашитых в вёрстку, быть не должно.

| Файл           | Что в нём                                                       |
| -------------- | --------------------------------------------------------------- |
| `types.ts`     | типы: `Crane`, `Sample`, `Interval`, `TimelineEvent`, `DayData` |
| `fleet.ts`     | статический парк из 8 кранов — якорные значения                 |
| `telemetry.ts` | генератор суточного ряда, интервалов и событий                  |
| `rng.ts`       | детерминированный ГПСЧ (FNV-1a + mulberry32)                    |
| `time.ts`      | демо-время, работа с датами-ключами                             |
| `format.ts`    | форматирование чисел, времени и единиц                          |

## Демо-время

```
DEMO_NOW      = 02.09.2026 11:39   // как в макете и на скриншотах
DEMO_NOW_MIN  = 699                // минута суток
STEP_MIN      = 5                  // шаг ряда → 288 точек в сутках
```

«Сегодня» — это `2026-09-02`, а не системная дата. Так стенд выглядит
одинаково в любой день; с `new Date()` демо, открытое ночью, оказалось бы
пустым. Даты позже `DEMO_NOW` считаются будущим и данных не имеют.

## Кран (`fleet.ts`)

У каждого крана четыре блока:

- `passport` — грузоподъёмность, максимальная стрела, опорный контур,
  противовес, моточасы, калибровка, срок ТО;
- `current` — мгновенные значения **на DEMO_NOW**: режим, загрузка, масса,
  геометрия, обороты, температуры, давление, топливо, крен;
- `shift` — итоги смены: наработка, простой, циклы, поднятый вес,
  перегрузы, максимальная загрузка;
- `systems` — CAN, GPS, датчики угла и давления, связь, GSM, спутники.

`current` — это **якорь**: генератор строит сутки так, чтобы в момент
`DEMO_NOW` сойтись ровно к этим числам. Поэтому карточка на главном экране
и «Обзор» в мониторинге показывают одно и то же.

Краны без связи описываются полем `lastSeenMin`:

```
null  — кран на связи, данные идут до DEMO_NOW
число — минута суток, после которой связи нет
-1    — данных за сутки нет вообще
```

## Генератор (`telemetry.ts`)

### Зачем он нужен

В макете хронология нарисована процентами ширины полосок. Чтобы плеер
реально работал, нужен ряд точек во времени — из него считается и полоса,
и таблица интервалов, и все показатели под курсором.

### Как строятся сутки

1. **Seed** = `id крана + дата`. Один и тот же день всегда даёт один и тот
   же результат — иначе «Архив» разъезжался бы при каждом открытии.
2. **План суток** — последовательность блоков:
   `стоянка → прогрев и установка опор → циклы подъёма с паузами → стоянка`,
   а для кранов без связи в хвосте — блок `offline`.
3. **Подгонка под якорь.** Для «сегодня» длина рабочего окна, число циклов
   и простой берутся из `shift`, а окно заканчивается ровно на `DEMO_NOW`.
   Если кран сейчас под грузом, последним ставится незавершённый цикл —
   поэтому в момент курсора режим совпадает с `current.mode`.
4. **Точки** считаются с шагом 5 минут плюс отдельная точка ровно на
   «сейчас», чтобы последнее значение не отставало от `DEMO_NOW`.
5. **Последняя точка перезаписывается якорем** из `fleet.ts`.

### Профиль цикла подъёма

Доля цикла `f` → режим и загрузка:

```
0.00–0.16  подъезд, без груза
0.16–0.30  подъём, загрузка растёт до пика
0.30–0.70  перенос, загрузка у пика
0.70–0.84  опускание, загрузка падает
0.84–1.00  отход, без груза
```

Пики циклов раскладываются так, чтобы максимум смены был реально достигнут,
а число циклов с перегрузом совпало с `shift.overloads`.

### Связанные величины

Геометрия не набор независимых чисел:

```
вылет  = длина_стрелы · cos(угол) − 0.85
высота = длина_стрелы · sin(угол) + 0.10
```

Проверено на данных макета: SANY, 31.56 м при 68.26° → 10.84 м и 29.40 м —
ровно те значения, что на скриншоте. Допустимая масса падает с ростом
вылета по кривой, подобранной так, чтобы на якорном вылете крана
получалось его якорное «Допустимо»; масса груза = `допустимо × загрузка`.

### Что генератор отдаёт

`getDay(craneId, dateKey)` → `DayData`:

- `samples` — ряд точек `Sample` (телеметрия + накопители: циклы,
  наработка, простой, поднятый вес, перегрузы);
- `intervals` — однородные отрезки суток для таблицы «Интервалы работы»;
- `events` — события (начало работы, опоры, завершение цикла,
  предупреждение, перегруз, потеря связи), новые сверху;
- `cutoffMin` — минута, после которой данных ещё нет.

Результат кешируется по ключу `id|дата`.

Ещё две функции: `getRange(craneId, endDate, days)` — ряд за несколько
суток подряд (диапазон «7 дней»), и `indexAt` / `sampleAt` — поиск точки по
времени бинарным поиском (сетка неравномерна из-за точки на «сейчас»).

## Подводные камни

- **Накопители обнуляются в полночь.** Для диапазона «7 дней» нельзя брать
  `cyclesDone` последней точки — надо суммировать итоги каждых суток
  (так сделано в `TimelineTab.accumulate`).
- **`loadPct` может быть `null`** — кран без связи. Каждое место, где
  считается цвет или процент, обязано это переживать.
- **`Math.random()` в домене запрещён** — ломает воспроизводимость архива.
