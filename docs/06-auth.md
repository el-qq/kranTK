# Демонстрационный вход

## Как работает

Пара **`demo` / `demo`**. Логин нечувствителен к регистру и пробелам по
краям, пароль сверяется точно. Код — `src/features/auth/useAuth.ts`,
форма — `src/features/auth/LoginScreen.tsx`.

Признак входа хранится в `sessionStorage` под ключом `kran-tk.session`:

```json
{ "login": "demo", "since": 1788331393732 }
```

`sessionStorage`, а не `localStorage`: сессия живёт до закрытия вкладки, и
демо-стенд на общем компьютере не остаётся открытым «навсегда». Если
хранилище недоступно (приватный режим), приложение работает в памяти —
вход просто не переживёт перезагрузку.

`App` рендерит `LoginScreen`, пока сессии нет, и не монтирует ни один
экран приложения. Кнопка «Выход» в меню чистит ключ и возвращает форму.

## Ограничения — важно

**Это витрина доступа, а не защита.**

- Пароль лежит в клиентском коде, а исходники сайта публичны: любой может
  открыть бандл и прочитать его.
- Проверка выполняется в браузере, обойти её тривиально.
- Сборка со всеми данными уже загружена к моменту показа формы —
  форма ничего не скрывает физически.

Отсюда правило: **за этой формой нельзя держать ничего, что нельзя
показывать**. Все данные стенда — вымышленные и генерируемые на месте.

## Если понадобится настоящая защита

Клиентской проверкой её не сделать в принципе — нужен сервер:

- вынести приложение с GitHub Pages туда, где есть бэкенд, и проверять
  учётные данные на нём;
- либо закрыть статику базовой аутентификацией на уровне хостинга
  (Cloudflare Access, nginx `auth_basic`, Netlify password protection);
- либо оставить Pages, но приватным репозиторием с доступом по
  учётным записям GitHub.

Менять форму под «более сложный пароль» смысла нет: она останется
клиентской.
