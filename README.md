# Crane Monitor · демо-стенд

Статическая демонстрация системы мониторинга автокранов:
парк из 8 машин, загрузка и перегрузы, геометрия стрелы, наработка и циклы,
состояние двигателя, гидравлики и связи, **рабочая хронология смены** с
воспроизведением и перемоткой.

Бэкенда нет: вся телеметрия считается в браузере детерминированным
генератором, поэтому архив за любую дату воспроизводим.

**Вход:** `demo` / `demo`
(это витрина доступа, а не защита — см. [docs/06-auth.md](docs/06-auth.md)).

## Локальный запуск

Нужен [Node.js](https://nodejs.org) 22.12 или новее — подойдёт и 20.19+
(этого требует Vite 8). Проверить: `node -v`.

### Быстрее всего — одной командой

```bash
npm install
npm start
```

Проект соберётся, поднимется локальный сервер и откроется браузер на
**http://localhost:4173**. Дальше вход `demo` / `demo`.

Если не хочется набирать команды, есть готовые запускалки — они сами
проверят Node и при необходимости поставят зависимости:

```bash
./scripts/start.sh      # macOS, Linux
scripts\start.cmd       # Windows
```

### Для разработки

```bash
npm run dev
```

Dev-сервер на **http://localhost:5173** с горячей перезагрузкой: правки в
`src/` видны сразу, без пересборки.

### Без сервера вообще — один HTML-файл

```bash
npm run build:standalone
```

Получится `dist-standalone/kran-monitor.html` (~300 КБ) со вшитыми стилями
и скриптами. Его можно открыть двойным кликом с диска, скинуть на флешку
или отправить письмом — Node и интернет не нужны. Удобно показывать стенд
на чужом ноутбуке.

> Без сети шрифты Roboto не подгрузятся и текст отрисуется системным
> Arial — на работу это не влияет. Вход при открытии с диска может не
> пережить перезагрузку страницы: часть браузеров не даёт файлам с диска
> доступ к хранилищу сессии.

Подробности и решение проблем — [docs/08-local-run.md](docs/08-local-run.md).

## Все команды

| Команда                    | Что делает                                       |
| -------------------------- | ------------------------------------------------ |
| `npm start`                | собрать и открыть стенд на http://localhost:4173 |
| `npm run dev`              | dev-сервер с горячей перезагрузкой               |
| `npm run build`            | сборка в `dist/`                                 |
| `npm run preview`          | отдать уже собранный `dist/` локально            |
| `npm run build:standalone` | автономный HTML-файл в `dist-standalone/`        |
| `npm run typecheck`        | проверка типов                                   |
| `npm run format`           | автоформатирование (Prettier)                    |
| `npm run format:check`     | проверка форматирования без правок               |

## Что реализовано

- **Главный экран** — сводка по парку, лента «Требует внимания»,
  раскрывающиеся карточки кранов, карта, матрица загрузки за 15 дней.
- **Мониторинг** — карточка крана: вкладки «Обзор» и «Хронология»,
  режимы Live / Архив, листание дат.

Разделы «Журнал», «Диагностика», «Отчёты» в демо не входят.

## Публикация

Push в `main` → GitHub Actions собирает и выкладывает на GitHub Pages.

Два обязательных условия: репозиторий **публичный** (на тарифе Free Pages
иначе недоступны) и один раз включён источник
**Settings → Pages → Source: GitHub Actions** — автоматически это сделать
нельзя, у `GITHUB_TOKEN` нет прав администратора репозитория.

Адрес зависит от имени репозитория, workflow подстраивается сам:

| Репозиторий            | Адрес                                  |
| ---------------------- | -------------------------------------- |
| `kranTK`               | `https://<владелец>.github.io/kranTK/` |
| `<владелец>.github.io` | `https://<владелец>.github.io/`        |

Чтобы стенд открывался как `krantk.github.io`, нужен владелец `krantk`
(аккаунт или организация) с публичным репозиторием `krantk.github.io`.
Подробности и разбор ошибок — [docs/07-deploy.md](docs/07-deploy.md).
